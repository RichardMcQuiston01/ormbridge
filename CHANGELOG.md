# CHANGELOG

## Unreleased

### Added

- ROADMAP: Phase 5 (Go ORMs) with GORM parser and emitter tracks.
- Laravel parser (track I; `parseLaravel`, `--from laravel`, `src/parsers/laravel.ts`, the `laravel` format; `.php` is not claimed, so pass `--from laravel`). Laravel's schema lives in migrations, so the parser replays the migration files in file-name order to rebuild the current schema and then reads the Eloquent models. Migrations: anonymous and named classes, `Schema::create` / `table` / `drop` / `dropIfExists` / `rename` / `dropColumns`, `dropColumn`, `renameColumn`, `->change()`, the `drop*` index, key, timestamp, soft delete, remember token and morph helpers (indexes by name or by column list, using Laravel's default index names), `up()` only, every column method (increments, integer, string, text, decimal, date and time, json, uuid, ulid, enum, `foreignId`, `foreignUuid`, `foreignIdFor`, `timestamps`, `softDeletes`, `rememberToken`, `morphs` and the geometry family with a warning), modifiers (`nullable`, `default` including `DB::raw`, `useCurrent`, `useCurrentOnUpdate`, `unique`, `index`, `primary`, `fullText`, `storedAs`, `constrained`, `references()->on()`, `onDelete` and the `cascadeOnDelete` family) and table-level `primary` / `unique` / `index` / `foreign`. Models: `$table`, `$casts` / `casts()` (backed enum, boolean, array, decimal, datetime), `$timestamps` with `CREATED_AT` / `UPDATED_AT`, `SoftDeletes`, `HasUuids`, `HasUlids`, inherited base models, and `hasOne` / `hasMany` / `belongsTo` / `belongsToMany` with custom keys and pivot tables, all following Laravel's naming conventions (checked against `illuminate/support` v13.35: table names from class names, `<model>_id` keys, `post_tag` pivot tables). Pivot tables that hold only the two keys (and optionally an `id` and timestamps) are folded into many-to-many fields; others stay models. Conditionals and loops in migrations, raw SQL, dynamic names, polymorphic and derived relations, composite and unresolvable foreign keys and tables that are never created produce warnings naming the table instead of being dropped silently.
- Laravel input discovery in `src/io.ts`: a project root reads `database/migrations` and `app/` (skipping `vendor/`, `storage/`, `tests/`, `bootstrap/cache`, `node_modules/` and `*Test.php`); directories passed on their own are read as given. Files are classified by content, so flat folders work. The Django-only skip list (which includes `migrations`) does not apply.
- Canonical Laravel fixture of the blog schema (`test/fixtures/laravel`): twelve timestamped migrations that add, rename, change and drop columns, create and drop a table, and add indexes and a foreign key later, plus Eloquent models and a backed enum; with goldens for Laravel to Django, Prisma, TypeORM, Doctrine, TypeScript and Graphene, and `test/laravel-parser.test.ts`. The fixture passes `php -l`, and its migrations were run in order by Illuminate v13.35 against SQLite (`test/tools/replay-laravel-migrations.php`; the comparison with the parser's result runs when `LARAVEL_DIR` points at a Composer directory with `illuminate/database`, `illuminate/events` and `illuminate/container`).
- Laravel is now readable and writable, so it joins the round-trip drift goldens (`roundtrip-*laravel*.drift.txt`) and the conversion matrix (`docs/CONVERSION_MATRIX.md`, regenerated). Three new documented reasons explain the differences that come from the Laravel writer: keys written as `id()` come back as big integers, `timestamps()` columns are nullable and maintained by Eloquent, and unnamed reverse relations get a plural method name. The reader understands the writer's `HasUuids` + `uniqueIds()` output (generated UUIDs on non-key columns) and does not give an auto-updated column a second `now` default.
- `src/parsers/phpSyntax.ts` now also exports `collectDeclarations`, `resolveClassName`, `readEnumDeclaration`, `argumentNodes` and `evaluateArguments`; the Doctrine parser uses the shared copies (no behaviour change).
- Doctrine parser (track G; `parseDoctrine`, `--from doctrine`, `src/parsers/doctrine.ts` and `src/parsers/phpSyntax.ts` on the tree-sitter PHP grammar). Reads PHP 8 attribute mappings: `#[ORM\Entity]`, `#[ORM\Table]`, `#[ORM\Column]` (DBAL types and `Types::` constants, `length`, `precision`, `scale`, `nullable`, `unique`, `name`, `options` defaults, `enumType`, types inferred from the PHP property type), `#[ORM\Id]` with `#[ORM\GeneratedValue]` / `#[ORM\CustomIdGenerator]` and composite keys, `ManyToOne` / `OneToOne` / `OneToMany` / `ManyToMany` with `JoinColumn`, `JoinTable`, `mappedBy` and `inversedBy`, `#[ORM\Index]` and `#[ORM\UniqueConstraint]`, PHP 8.1 backed enums, embeddables (`columnPrefix`), mapped superclasses and traits, single-table and joined inheritance, `#[ORM\Version]`, constructor promotion, namespaces, `use` aliases, group imports, direct imports and fully qualified names. Doctrine's underscore naming strategy supplies table, column, join column and embedded column names. Docblock annotations are detected and reported instead of silently producing an empty schema; XML and YAML mappings and docblock annotations are later work. `.php` is not claimed (pass `--from doctrine`); directory input reads `.php` files and skips `vendor/`, `var/` and `*Test.php`. Parse only for now; the emitter is track H.
- Canonical Doctrine fixture of the blog schema (`test/fixtures/doctrine`, validated with `php -l` and Doctrine ORM 3.7), with goldens for Doctrine to Django, Prisma, TypeORM, TypeScript and Graphene, and `test/doctrine-parser.test.ts`.
- Doctrine emitter (track H; `src/emitters/doctrine.ts`, `emitDoctrine`, the `doctrine` format; `.php` is not claimed, so pass `--to doctrine -o <directory>`). Writes PHP 8.1+ entity classes with attributes, one PSR-4 file per entity (`src/Entity/Post.php`) and one backed enum per enum (`src/Enum/PostStatus.php`) through the multi-file emit contract. Typed properties with correct nullability, `DateTimeImmutable` dates, `Collection` with `ArrayCollection` for to-many relations, explicit `#[ORM\Column]` types, lengths, precision/scale, `nullable`, `unique`, defaults and `enumType`, `#[ORM\Id]` / `#[ORM\GeneratedValue]` and composite keys, both sides of every relation (`ManyToOne` + `JoinColumn(onDelete:)` / `OneToMany`, `OneToOne`, `ManyToMany` + `JoinTable`) with matching `inversedBy` / `mappedBy`, getters and fluent setters, `add*` / `remove*` helpers that keep both sides in sync, class-level `#[ORM\Index]` / `#[ORM\UniqueConstraint]`, lifecycle callbacks for auto-updated timestamps, and backtick quoting of reserved SQL names. Both naming modes are supported. Unrepresentable constructs (arrays, hstore, ranges, durations, generated columns, views, composite foreign keys, Prisma-only constructs) produce warnings naming the model and field. Verified with `php -l` and with Doctrine ORM 3.7 (real metadata factory, `SchemaValidator`, SQLite schema creation and a persistence round trip); the real-Doctrine tests run when `DOCTRINE_DIR` points at a Composer directory with `doctrine/orm` and `symfony/cache`.
- Laravel emitter (track J; `src/emitters/laravel.ts`, `emitLaravel`, the `laravel` format; `.php` is not claimed, so pass `--to laravel -o <directory>`). Writes a Laravel 11 / 12 schema through the multi-file emit contract: one migration per table in `database/migrations/` (anonymous classes with `up()` and `down()`, deterministic names `2024_01_01_000001_create_posts_table.php` counting up by one, tables ordered so foreign keys point at earlier tables, dependency cycles broken with a later `add_foreign_keys_to_<table>_table` migration, self references inline), Blueprint columns (`id()`, `bigIncrements`, `uuid()` / `ulid()` keys, `string(n)`, `decimal(p, s)`, `dateTime`, `jsonb` / `json`, `enum`, `timestamps()`, `softDeletes()`, unsigned and sized integers from Prisma native types, `nullable()`, `unique()`, `default()`, `useCurrent()`, indexes and composite keys), `foreignId()->constrained()` / `foreignUuid` / `foreignUlid` with the matching referential-action helpers, pivot tables for many-to-many relations (Laravel's `post_tag` convention in `normalize`, `<table>_<relation>` in `preserve`), Eloquent models under `app/Models/` (`$table`, `$primaryKey`, `$keyType`, `$incrementing` and `$timestamps` only when they differ from the conventions, `$fillable`, `$casts` for enums, booleans, arrays, dates and decimals, `SoftDeletes`, `HasUuids` / `HasUlids`, typed `belongsTo` / `hasMany` / `hasOne` / `belongsToMany` methods on both sides with explicit keys only when non-conventional) and PHP 8.1 backed enums under `app/Enums/`. Both naming modes are supported. Arrays, hstore, ranges, durations, generated columns, views, composite foreign keys and other Prisma-only constructs produce warnings naming the model and field. Verified with `php -l` and with Illuminate 13 (every migration run up and down against in-memory SQLite, then the models loaded for a persistence round trip: both sides of every relationship, many-to-many attach and detach, enum casts, UUID and ULID keys, soft deletes); the real-Laravel tests run when `LARAVEL_DIR` points at a Composer directory with `illuminate/database`, `illuminate/events`, `illuminate/container`, `illuminate/support`, `ramsey/uuid` and `symfony/uid` (`test/tools/validate-laravel.php`).
- `--namespace`, the `namespace` config key and `FormatOptions.namespace` also set the namespace of the Laravel models (default `App\Models`; enums go in the sibling `Enums` namespace).
- `--namespace` flag, `namespace` config key and `FormatOptions.namespace` for the PHP namespace of Doctrine entities (default `App\Entity`; enums go in the sibling `Enum` namespace).
- Shared test harness handles multi-file output: `expectFilesMatchGolden` / `expectConversionMatchesGolden` compare a file map with the golden directory `test/golden/<pair>.<naming>/` (one golden per generated file, added and removed files are reported, `UPDATE_GOLDEN=1` rewrites the directory), round trips feed every emitted file back into the parser (`resultToSources`), `describeResultDrift` reports drift per file, and the matrix helpers keep the file map next to the joined text. A new test fails when `test/golden/` holds an entry no format pair produces. Single-text behaviour and every existing golden are unchanged; `test/harness.test.ts` covers the new paths with a test-only readable multi-file format.
- Prisma coverage (track F). The parser and emitter now handle composite foreign keys (`@relation(fields: [a, b], references: [x, y])` with `onDelete`, `onUpdate` and `map:`), `@@fulltext`, `view` blocks, `Unsupported(...)` (kept as an opaque column; the Postgres range types come back as range fields), `@db.*` native types for PostgreSQL, CockroachDB, MySQL, SQL Server and MongoDB (the accepted names were checked with `prisma validate` on Prisma 6.19 and 7.10; types the target provider rejects are dropped with a warning), `@@id(map:)` / `@id(map:)` / `@unique(map:)` / `@relation(map:)` constraint names, `@@index` options (`sort`, `length`, `ops`, `type`, `clustered`), `@@schema` and multiSchema (`schemas` in the datasource), enum `@@map` / `@@schema`, `@ignore` / `@@ignore`, `cuid()` / `ulid()` / `nanoid(n)` / `uuid(7)` / `dbgenerated("...")` / `auto()` / `sequence()` defaults, and scalar lists (now arrays instead of `Json`). The emitter adapts to the provider: `Restrict` becomes `NoAction` and enums become `String` on SQL Server, `Int` auto-increment becomes `sequence()` on CockroachDB, CockroachDB uses its own string types, named primary and foreign keys are dropped where the provider rejects them, and `@@fulltext`, index types and prefix lengths are only written where they are valid. Each adaptation warns with the model and field.
- Prisma 7 header: `emitPrisma` and `convertText` accept `prismaVersion: 7` to write the `prisma-client` generator with an `output` path and a datasource without `url` (the default stays Prisma 6). Views add `previewFeatures = ["views"]`, which both Prisma 6.19 and 7.10 require. No CLI flag yet.
- Additive IR changes (`src/ir.ts`): scalar type `unsupported`; `IrField.nativeType`, `unsupportedType`, `isIgnored` and `uniqueName`; `IrDefault` kinds `clientGenerated` and `dbExpression` and a `version` on `uuid`; `IrRelation.onUpdate` and `constraintName`; `IrModel.compositeForeignKeys` (new `IrCompositeForeignKey`), `isView`, `isIgnored`, `schema` and `primaryKeyName`; `IrIndex.kind`, `method`, `clustered` and `fieldOptions`; `IrEnum.dbName` and `schema`. The Django, TypeORM, TypeScript and Graphene emitters start their warnings with `prismaOnlyWarnings` (`src/prismaOnlyConstructs.ts`), which names the model and field of each of these constructs they cannot represent.
- `test/fixtures/prisma-extras` with `test/prisma-extras.test.ts` and goldens in `test/golden-extras/` (Prisma round trip, MySQL, SQL Server, CockroachDB and Prisma 7 output, and Django, TypeORM, TypeScript and Graphene conversions). Set `PRISMA_BIN` (and `PRISMA_MAJOR=7` for Prisma 7) to also run `prisma validate` on the emitted schemas.
- CLI polish (step 2.2). `ormbridge convert --dry-run` runs the whole conversion and reports each file it would create or update (lines, size, diff summary) and the warnings without writing. `--check` exits 3 and names the missing or stale file with a short diff summary when an output differs from the conversion, and exits 0 when everything is up to date (for CI). Exit codes are now 0 (ok), 1 (conversion error), 2 (usage or config error) and 3 (check failed); invalid flag values and unknown flags now exit 2 instead of 1. Unchanged output files are no longer rewritten.
- Config files: `ormbridge.config.json` or `.ormbridgerc.json` (JSON only), found from the current directory upward until a `package.json` directory or the filesystem root, or chosen with `--config <path>` and disabled with `--no-config`. Keys `input`, `output`, `from`, `to`, `naming`, `provider`, `header`, `appLabel`, `autoField`, and `conversions` for several named conversions that one `ormbridge convert` runs together. Flags override config values; errors name the offending key. `-i` is no longer required when a config supplies the input. New `src/config.ts` (`findConfigFile`, `loadConfigFile`, `parseConfig`) and error code `INVALID_CONFIG`.
- Multi-file emit contract (backwards compatible): `FormatAdapter.emit` may return `{ files, warnings }` (`MultiFileEmitOutput`, relative path to text) instead of `{ text, warnings }`; the union is `FormatEmitOutput`. `ConvertResult` gains an optional `files` (with an empty `output`). `runConversion` writes all files under the `-o` directory, supports `--dry-run` and `--check` per file, and errors clearly when `-o` is a file path or missing. No built-in emitter changed; a test-only adapter covers the path. Groundwork for the Laravel and Doctrine emitters.
- `RunOptions.dryRun` and `RunOptions.check`, `RunSummary.plannedFiles` and `RunSummary.written`; the CLI logic moved to `src/cliRunner.ts` (`runCli`) so it can be tested in-process.
- Django coverage (track E). The parser and emitter now handle `django.contrib.postgres` `ArrayField` (including nested arrays and `base_field` options), `HStoreField` and the five range fields; `GenericIPAddressField` / `IPAddressField` and `DurationField` as their own types; `GeneratedField` (expression carried as source text, `db_persist`); `db_default` (`Value(...)`, `Now()`, literals); `models.CompositePrimaryKey`; proxy models (merged into the concrete model, relations retargeted, with a warning); `Meta.swappable` (resolves `settings.AUTH_USER_MODEL` and `get_user_model()` without assuming `User`); custom managers and querysets ignored without warnings; and skips partial `UniqueConstraint(condition=...)` and `GenericForeignKey` with a warning. The Django emitter writes all of these back, with the postgres imports.
- Additive IR changes (`src/ir.ts`): scalar types `duration`, `ipAddress`, `hstore` and `range`, and optional `IrField` properties `arrayDepth`, `rangeOf`, `generated` and `isDbDefault`. The Prisma, TypeORM, TypeScript and Graphene emitters map them (scalar lists, `array: true`, `T[]`, `graphene.List`) or degrade with a warning naming the model and field. `PyCall` in `pythonSyntax.ts` gained a `text` property.
- `test/fixtures/django-extras` with `test/django-extras.test.ts` and goldens in `test/golden-extras/` for Django to Prisma, TypeORM, TypeScript and Graphene plus a Django round trip.
- Conversion matrix (`test/conversion-matrix.test.ts`, `test/irCompare.ts`): for every ordered pair of readable and writable formats (discovered from the registry), the canonical fixture is read, written in the other format, read back, and the two intermediate representations are compared with a normalising comparator (ignores ordering, identifier spelling, synthesized names and documented-equivalent spellings; reports structured differences). Also checks that every loss is explained, that A to B to A to B is stable, and that written text reads back without errors.
- `docs/CONVERSION_MATRIX.md`: generated summary matrix and per-pair list of what is lossy and why, built by `npm run docs:matrix` (`scripts/generate-conversion-matrix.ts`, run with the new `tsx` dev dependency). A test fails when the committed document is stale; `UPDATE_GOLDEN=1 npm test` regenerates it. Linked from the README.
- Graphene emitter (`src/emitters/graphene.ts`, `emitGraphene`, output-only `graphene` format; `.py` is not claimed, so pass `--to graphene`). Writes a graphene-django module that pairs with Django models: a `DjangoObjectType` per model with an explicit `Meta.fields` list (including reverse relations), a `Query` with single-item and list fields, create/update/delete `graphene.Mutation` classes with input types derived from the IR scalar types (required from nullability, relations as `ID`), and the final `graphene.Schema`. Enums use graphene-django choice conversion for output and `String` inputs. Unrepresentable constructs (binary columns, relations to missing models, composite primary keys) produce warnings naming the model and field. Tests check that the output compiles as Python.
- TypeScript interfaces emitter (`src/emitters/typescriptInterfaces.ts`, `emitTypescriptInterfaces`, the output-only `typescript` format; pass `--to typescript` because `.ts` is not inferred). Writes one `export interface` per model and string `export enum`s for enums, with `| null` for nullable fields, foreign-key scalars plus optional expanded relations and reverse lists, and JSON-friendly types (`string` for dates, decimals, big integers and UUIDs, `unknown` for JSON). A programmatic `dates: 'date'` option types dates as `Date`. Both naming modes are supported; unrepresentable constructs produce warnings naming the model and field. Tests compile the output of every source with the TypeScript compiler API.
- TypeORM parser (`parseTypeorm`, `--from typeorm`): reads entity classes with the tree-sitter TypeScript grammar. Supports `@Entity` names, `@Column` options (type, length, nullable, unique, default, precision/scale, enum), `@PrimaryGeneratedColumn` (increment/uuid), `@PrimaryColumn` (including composite keys), `@CreateDateColumn` / `@UpdateDateColumn`, `@OneToOne` / `@ManyToOne` / `@OneToMany` / `@ManyToMany` with `@JoinColumn` / `@JoinTable` and `onDelete`, `@Index`, `@Unique`, TypeScript enums and string lists, embedded entities and base-class inheritance. Unsupported constructs produce warnings naming the entity and column. Directory input with `--from typeorm` picks up `.ts` files (excluding `.d.ts`, `.test.ts` and `.spec.ts`).
- Canonical TypeORM fixture of the blog schema, with goldens for TypeORM to Django and Prisma.
- TypeORM emitter (`src/emitters/typeorm.ts`, `emitTypeorm`, the `typeorm` format is read and write; `.ts` is not inferred, so pass `--from typeorm` or `--to typeorm`). Writes entity classes with typed properties, `@PrimaryGeneratedColumn` / `@PrimaryColumn`, `@Column` with explicit types, TypeScript enums, `@CreateDateColumn` / `@UpdateDateColumn`, owning and inverse relation decorators with `@JoinColumn` / `@JoinTable` and `onDelete`, and class-level `@Index` / `@Unique`. Both naming modes are supported; unrepresentable constructs produce warnings naming the model and field.
- Shared test harness: a canonical schema per format (`test/fixtures/canonical.ts`), golden-file comparisons for every readable/writable format pair in both naming modes, and round-trip drift files that document lossy mappings. See `test/README.md`.
- Format registry (`src/formats.ts`) with a `FormatAdapter` interface (`name`, `extensions`, `description`, optional `parse` and `emit`) and `registerFormat`, `getFormat`, `getFormatByExtension`, `listFormats` and `listFormatNames` helpers, exported from the package. Django and Prisma are registered as adapters.
- `ormbridge formats` command listing each format with its file extensions and whether it can be read and/or written.
- ESLint (typescript-eslint) with `lint`, `lint:fix`, `format` and `format:check` scripts.
- GitHub Actions CI running lint, format check, build and tests on pull requests and pushes to `dev` and `main`.
- Publish workflow for `v*.*.*` tags: verifies the tag matches `package.json` and the commit is on `main`, runs lint, format check, build and tests, then publishes to npm with provenance. Prerelease versions publish under the `next` dist-tag.

### Changed

- `convertText` and the CLI look formats up in the registry instead of hard-coding Django and Prisma. Unknown formats, and formats that cannot be read or written, return descriptive errors. `FormatName` is now a `string`; `FORMAT_NAMES` still lists the built-in formats.
- Pinned TypeScript to 6.x because typescript-eslint does not yet support TypeScript 7.
- Formatted the codebase with Prettier.
