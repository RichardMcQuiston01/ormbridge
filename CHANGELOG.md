### Changed

- TypeORM emitter: a Prisma `view` block is written as `@ViewEntity({ name, expression })` with `@ViewColumn()` columns instead of a key-less `@Entity`, which TypeORM rejected when building its metadata. A Prisma view has no SQL definition, so the `expression` is the placeholder `'SELECT * FROM <view>'` (it selects from the view itself, so `synchronize` cannot create it) with a TODO comment and a warning that the expression must be completed. Primary key, unique and index information on a view and relations on a view are dropped with a warning. `prismaOnlyWarnings` takes an optional `viewsSupported` flag so the generic "written like a regular table" warning is not given for TypeORM; the other emitters are unchanged.
- TypeORM parser: `@ViewEntity` classes are read as `isView` models (name from the first argument or the `name` option, columns from `@ViewColumn`) instead of being skipped, so a TypeORM-to-Prisma round trip returns a `view` block. The view `expression` is not converted (a warning says so), and a view without a key no longer warns about a missing primary key.
- Real-tool verification: the prisma-extras fixture keeps its view for the TypeORM check, which builds TypeORM's metadata for it (all four providers) and checks the table type and columns; SQLite synchronization skips the view because of its self-referencing placeholder. Django and Graphene verification still strip views (`SOURCES_WITHOUT_VIEWS` in `test/realToolSupport.ts`). The `prisma-to-typeorm` extras golden is updated.
- CI: a second job, `real-tools` (`.github/workflows/ci.yml`), installs Django and graphene-django (Python 3.12 venv), TypeORM with better-sqlite3, pg, mysql2 and mssql (`test/tools/setup-verification-tools.sh`), PHP 8.3 with Doctrine ORM and Illuminate (Composer), Prisma 6 and 7 and Go, and runs the whole suite with `DJANGO_PYTHON`, `TYPEORM_DIR`, `DOCTRINE_DIR`, `LARAVEL_DIR` and `PRISMA_BIN` set, so the optional real-tool verification tests no longer skip there; the `check` job (lint, format, build, test) is unchanged and stays fast. The PHP `php -l`, Doctrine, Illuminate and `prisma validate` tests now carry an explicit 120 s timeout instead of vitest's 5 s default.

Adds GORM (Go) as a readable and writable format, a `--prisma-version` flag, a Doctrine parser that recovers lifecycle callbacks and constructor defaults, and optional verification of the Django, Graphene and TypeORM output against the real tools.

### Added

- Real-tool verification of the Django, Graphene and TypeORM output, in the same optional style as Doctrine, Laravel, Prisma and GORM (`test/django-verify.test.ts`, `test/graphene-verify.test.ts`, `test/typeorm-verify.test.ts`, `test/realToolSupport.ts`, `test/tools/validate-django.py`, `validate-graphene.py`, `validate-typeorm.ts` and `setup-verification-tools.sh`). Django: `check`, `makemigrations --dry-run`, `makemigrations`, `sqlmigrate` and `migrate` on in-memory SQLite, then model metadata and the migrated database are compared with the IR. Graphene: the generated schema is imported next to the generated models, built, introspected and queried (list queries and a create, get, update, delete round trip). TypeORM: the entities of every provider are compiled with `tsc`, TypeORM's metadata is built and compared, and the SQLite entities are synchronized into in-memory SQLite and compared (tables, columns, foreign keys, unique constraints, indexes). The canonical blog schema read from every other format and the prisma, django and gorm extras fixtures are covered, in both naming modes. Set `DJANGO_PYTHON` and `TYPEORM_DIR` (see `test/README.md`); each test is skipped with a reason when its tool is missing, and CI is unchanged.
- Doctrine parser reads what the Doctrine writer puts outside the mapping attributes, so Doctrine round trips keep it. A `#[ORM\PreUpdate]` method that assigns `$this->prop = new \DateTimeImmutable();` sets the field's "updated automatically" flag (a `#[ORM\PrePersist]`-only callback becomes a `now` default). `__construct` assignments (`self::generateUuid()`, `Uuid::v4()`, enum cases, scalar literals, array literals for JSON columns, `new \DateTimeImmutable()`) and property initialisers (`private int $views = 0;`, `= []`) become the field default; a column `options: ['default' => ...]` takes precedence. Other callback statements and values that cannot be evaluated statically are ignored with a warning. Tests: `test/doctrine-behaviour.test.ts` and the fixture `test/fixtures/doctrine-behaviour/`.
- Conversion matrix: the reasons `doctrine-lifecycle-callback` and `doctrine-constructor-default` are gone because those losses no longer occur. Two reasons are new: PHP's single empty array literal turns an empty JSON object default into `[]`, and GORM cannot keep an empty string default (visible now that the Doctrine reader returns `private string $body = '';`).
- GORM parser (track K; `parseGorm`, `--from gorm`, `src/parsers/gorm.ts`, `src/parsers/goSyntax.ts`, the read-only `gorm` format; `.go` is not claimed, so pass `--from gorm`). Names follow GORM's conventions (snake_case columns with its initialisms, pluralised table names with the `jinzhu/inflection` rules, `ID` primary key, `<Field>ID` foreign keys), so the database names are reproduced exactly; the test fixtures are verified against GORM v1.31's own schema parser when Go is installed.

## 0.2.0 - 2026-10-09

First public release. ormbridge converts ORM models between Django, Prisma, TypeORM, Doctrine and Laravel (all readable and writable), and writes TypeScript interfaces and Graphene schemas. See the README for usage and `docs/CONVERSION_MATRIX.md` for what survives a round trip.

### Added

- ROADMAP: Phase 5 (Go ORMs) with GORM parser and emitter tracks.
- Laravel parser (track I; `parseLaravel`, `--from laravel`, `src/parsers/laravel.ts`, the `laravel` format; `.php` is not claimed, so pass `--from laravel`). Laravel's schema lives in migrations, so the parser replays the migration files in file-name order to rebuild the current schema and then reads the Eloquent models. Migrations: anonymous and named classes, `Schema::create` / `table` / `drop` / `dropIfExists` / `rename` / `dropColumns`, `dropColumn`, `renameColumn`, `->change()`, the `drop*` index, key, timestamp, soft delete, remember token and morph helpers (indexes by name or by column list, using Laravel's default index names), `up()` only, every column method (increments, integer, string, text, decimal, date and time, json, uuid, ulid, enum, `foreignId`, `foreignUuid`, `foreignIdFor`, `timestamps`, `softDeletes`, `rememberToken`, `morphs` and the geometry family with a warning), modifiers (`nullable`, `default` including `DB::raw`, `useCurrent`, `useCurrentOnUpdate`, `unique`, `index`, `primary`, `fullText`, `storedAs`, `constrained`, `references()->on()`, `onDelete` and the `cascadeOnDelete` family) and table-level `primary` / `unique` / `index` / `foreign`.
