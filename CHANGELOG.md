# CHANGELOG

## Unreleased

### Added

- CLI polish (step 2.2). `ormbridge convert --dry-run` runs the whole conversion and reports each file it would create or update (lines, size, diff summary) and the warnings without writing. `--check` exits 3 and names the missing or stale file with a short diff summary when an output differs from the conversion, and exits 0 when everything is up to date (for CI). Exit codes are now 0 (ok), 1 (conversion error), 2 (usage or config error) and 3 (check failed); invalid flag values and unknown flags now exit 2 instead of 1. Unchanged output files are no longer rewritten.
- Config files: `ormbridge.config.json` or `.ormbridgerc.json` (JSON only), found from the current directory upward until a `package.json` directory or the filesystem root, or chosen with `--config <path>` and disabled with `--no-config`. Keys `input`, `output`, `from`, `to`, `naming`, `provider`, `header`, `appLabel`, `autoField`, and `conversions` for several named conversions that one `ormbridge convert` runs together. Flags override config values; errors name the offending key. `-i` is no longer required when a config supplies the input. New `src/config.ts` (`findConfigFile`, `loadConfigFile`, `parseConfig`) and error code `INVALID_CONFIG`.
- Multi-file emit contract (backwards compatible): `FormatAdapter.emit` may return `{ files, warnings }` (`MultiFileEmitOutput`, relative path to text) instead of `{ text, warnings }`; the union is `FormatEmitOutput`. `ConvertResult` gains an optional `files` (with an empty `output`). `runConversion` writes all files under the `-o` directory, supports `--dry-run` and `--check` per file, and errors clearly when `-o` is a file path or missing. No built-in emitter changed; a test-only adapter covers the path. Groundwork for the Laravel and Doctrine emitters.
- `RunOptions.dryRun` and `RunOptions.check`, `RunSummary.plannedFiles` and `RunSummary.written`; the CLI logic moved to `src/cliRunner.ts` (`runCli`) so it can be tested in-process.
- Django coverage (track E). The parser and emitter now handle `django.contrib.postgres` `ArrayField` (including nested arrays and `base_field` options), `HStoreField` and the five range fields; `GenericIPAddressField` / `IPAddressField` and `DurationField` as their own types; `GeneratedField` (expression carried as source text, `db_persist`); `db_default` (`Value(...)`, `Now()`, literals); `models.CompositePrimaryKey`; proxy models (merged into the concrete model, relations retargeted, with a warning); `Meta.swappable` (resolves `settings.AUTH_USER_MODEL` and `get_user_model()` without assuming `User`); custom managers and querysets ignored without warnings; and skips partial `UniqueConstraint(condition=...)` and `GenericForeignKey` with a warning. The Django emitter writes all of these back, with the postgres imports.
- Additive IR changes (`src/ir.ts`): scalar types `duration`, `ipAddress`, `hstore` and `range`, and optional `IrField` properties `arrayDepth`, `rangeOf`, `generated` and `isDbDefault`. The Prisma, TypeORM, TypeScript and Graphene emitters map them (scalar lists, `array: true`, `T[]`, `graphene.List`) or degrade with a warning naming the model and field. `PyCall` in `pythonSyntax.ts` gained a `text` property.
- `test/fixtures/django-extras` with `test/django-extras.test.ts` and goldens in `test/golden-extras/` for Django to Prisma, TypeORM, TypeScript and Graphene plus a Django round trip.
- Conversion matrix (`test/conversion-matrix.test.ts`, `test/irCompare.ts`): for every ordered pair of readable and writable formats (discovered from the registry), the canonical fixture is read, written in the other format, read back, and the two intermediate representations are compared with a normalising comparator (ignores ordering, identifier spelling, synthesized names and documented-equivalent spellings; reports structured differences). Also checks that every loss is explained, that A to B to A to B is stable, and that written text reads back without errors.
- `docs/CONVERSION_MATRIX.md`: generated summary matrix and per-pair list of what is lossy and why, built by `npm run docs:matrix` (`scripts/generate-conversion-matrix.ts`, run with the new `tsx` dev dependency). A test fails when the committed document is stale; `UPDATE_GOLDEN=1 npm test` regenerates it. Linked from the README.
- Graphene emitter (`src/emitters/graphene.ts`, `emitGraphene`, output-only `graphene` format; `.py` is not claimed, so pass `--to graphene`). Writes a graphene-django module that pairs with Django models: a `DjangoObjectType` per model with an explicit `Meta.fields` list (including reverse relations), a `Query` with single-item and list fields, create/update/delete `graphene.Mutation` classes with input types derived from the IR scalar types (required from nullability, relations as `ID`), and the final `graphene.Schema`. Enums use graphene-django choice conversion for output and `String` inputs. Unrepresentable constructs (binary columns, relations to missing models, composite primary keys) produce warnings naming the model and field. Tests check that the output compiles as Python.
- TypeScript interfaces emitter (`src/emitters/typescriptInterfaces.ts`, `emitTypescriptInterfaces`, the output-only `typescript` format; pass `--to typescript` because `.ts` is not inferred). Writes one `export interface` per model and string `export enum`s for enums, with `| null` for nullable fields, foreign-key scalars plus optional expanded relations and reverse lists, and JSON-friendly types (`string` for dates, decimals, big integers and UUIDs, `unknown` for JSON). A programmatic `dates: 'date'` option types dates as `Date`. Both naming modes are supported; unrepresentable constructs produce warnings naming the model and field. Tests compile the output of every source with the TypeScript compiler API.
- TypeORM parser (`parseTypeorm`, `--from typeorm`): reads entity classes with the tree-sitter TypeScript grammar. Supports `@Entity` names, `@Column` options (type, length, nullable, unique, default, precision/scale, enum), `@PrimaryGeneratedColumn` (increment/uuid), `@PrimaryColumn` (including composite keys), `@CreateDateColumn` / `@UpdateDateColumn`, `@OneToOne` / `@ManyToOne` / `@OneToMany` / `@ManyToMany` with `@JoinColumn` / `@JoinTable` and `onDelete`, `@Index`, `@Unique`, TypeScript enums and string lists, embedded entities and base-class inheritance. Unsupported constructs produce warnings naming the entity and column. Directory input with `--from typeorm` picks up `.ts` files (excluding `.d.ts`, `.test.ts` and `.spec.ts`).
- Canonical TypeORM fixture of the blog schema, with goldens for TypeORM to Django and Prisma.
- TypeORM emitter (`src/emitters/typeorm.ts`, `emitTypeorm`, the `typeorm` format is read and write; `.ts` is not inferred, so pass `--from typeorm` or `--to typeorm`). Writes entity classes with typed properties, `@PrimaryGeneratedColumn` / `@PrimaryColumn`, `@Column` with explicit types, TypeScript enums, `@CreateDateColumn` / `@UpdateDateColumn`, owning and inverse relation decorators with `@JoinColumn` / `@JoinTable` and `onDelete`, and class-level `@Index` / `@Unique`. Both naming modes are supported; unrepresentable constructs produce warnings naming the model and field.
- Shared test harness: a canonical schema per format (`test/fixtures/canonical.ts`), golden-file comparisons for every readable/writable format pair in both naming modes, and round-trip drift files that document lossy mappings. See `test/README.md`.
- Format registry (`src/formats.ts`) with a `FormatAdapter` interface (`name`, `extensions`, `description`, optional `parse` and `emit`) and `registerFormat`, `getFormat`, `getFormatByExtension`, `listFormats` and `listFormatNames` helpers, exported from the package. Django and Prisma are registered as adapters.
- `ormbridge formats` command listing each format with its file extensions and whether it can be read and/or written.
- ESLint (typescript-eslint) with `lint`, `lint:fix`, `format` and `format:check` scripts.
- GitHub Actions CI running lint, format check, build and tests on pull requests and pushes to `dev` and `main`.
- Publish workflow for `v*.*.*` tags: verifies the tag matches `package.json` and the commit is on `main`, runs lint, format check, build and tests, then publishes to npm with provenance. Prerelease versions publish under the `next` dist-tag.

### Changed

- `convertText` and the CLI look formats up in the registry instead of hard-coding Django and Prisma. Unknown formats, and formats that cannot be read or written, return descriptive errors. `FormatName` is now a `string`; `FORMAT_NAMES` still lists the built-in formats.
- Pinned TypeScript to 6.x because typescript-eslint does not yet support TypeScript 7.
- Formatted the codebase with Prettier.
