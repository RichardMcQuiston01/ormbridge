# Hibernate / JPA example

This folder shows ormbridge converting the shared blog schema to Hibernate / JPA entities (Java) and back.

- `ormbridge.config.json` defines two conversions: `to-jpa` and `from-jpa`.
- `models/` is generated from `../schema/schema.prisma`: `models/app/models/` holds one `@Entity` class per model (`Post.java` with `@Table`, `@Column`, `@ManyToOne`, `@JoinColumn`, `@OnDelete` and `@ColumnDefault`), the `PostStatus` enum with its `PostStatusConverter` (the stored values are lower case, so the enum cannot be stored by name), and the `PostTags` join model.
- `prisma/schema.prisma` is generated by reading `models/` back. It is the same schema as the shared one, apart from what JPA spells differently (the order of the `@@unique` and `@@index` lines, for example).

JPA claims no file extension (`.java` is too generic), so the config names `from` and `to` explicitly. The default `jakarta` style writes `jakarta.persistence` entities for Hibernate 6 and Spring Boot 3; add `"style": "javax"` to a conversion for `javax.persistence` and Hibernate 5, and `"namespace": "com.shop.data"` to change the Java package (default `app.models`, which is also the folder below `models/`).

Run it (the config file supplies the paths and formats):

```bash
cd examples/jpa
npx ormbridge convert           # regenerate models/ and prisma/schema.prisma
npx ormbridge convert --check   # exit code 3 if a generated file is stale
```

Inside this repository, run `npm run build` once and use `node ../../dist/cli.js convert` instead of `npx ormbridge convert`. `npm run examples` regenerates every example and `npm run examples:check` verifies them.

To use the entities, copy `models/app/models/` into a Maven or Gradle project with `hibernate-core` 6 (and `jackson-databind`, which Hibernate 6 uses for the JSON column), and give Hibernate a connection, for example with Spring Boot:

```properties
spring.datasource.url=jdbc:postgresql://localhost/blog
spring.jpa.hibernate.ddl-auto=validate
```

The files are generated, so edit `../schema/schema.prisma` and rerun rather than editing them. A Spring Boot project that relies on `CamelCaseToUnderscoresNamingStrategy` is unaffected: every table and column is named explicitly. See the [Hibernate / JPA guide](../../docs/formats/jpa.md) for what is read, written and lost.
