# Hibernate / JPA example

This folder shows ormbridge reading Hibernate / JPA entities (Java) and converting them to a Prisma schema. JPA is an input-only format for now, so there is no `to-jpa` conversion.

- `ormbridge.config.json` defines one conversion: `from-jpa`.
- `models/` holds the JPA model, written by hand: entity classes with `jakarta.persistence` annotations (`Post.java`, `Category.java`, ...), a `@MappedSuperclass` (`TimeStamped.java`), the `PostStatus` enum, and the many-to-many `@JoinTable` on `Post.tags`. They describe the same blog schema as [`../schema/schema.prisma`](../schema/schema.prisma). This is one of the examples whose `models/` folder is not generated, so edit these files freely.
- `prisma/schema.prisma` is generated by reading `models/`. It is the same schema as the shared one, except for the names JPA implies: a column without `@Column(name)` keeps its Java name (`viewCount`, not `view_count`), and a table without `@Table(name)` is the class name.

JPA claims no file extension (`.java` is too generic), so the config names `from` explicitly. Nothing is compiled or run: no JDK, Maven or database is needed.

Run it (the config file supplies the paths and formats):

```bash
cd examples/jpa
npx ormbridge convert           # regenerate prisma/schema.prisma
npx ormbridge convert --check   # exit code 3 if the generated file is stale
```

Inside this repository, run `npm run build` once and use `node ../../dist/cli.js convert` instead of `npx ormbridge convert`. `npm run examples` regenerates every example and `npm run examples:check` verifies them.

A Spring Boot project names tables and columns with `CamelCaseToUnderscoresNamingStrategy` (`blog_post`, `view_count`), which is configured in `application.properties` and is not read. Add `"naming": "normalize"` to the conversion to get snake_case names; see [the JPA guide](../../docs/formats/jpa.md#names).
