# Entity Framework Core example

This folder shows ormbridge reading Entity Framework Core models (C#) and converting them to a Prisma schema. EF Core is an input-only format, so there is no `to-efcore` conversion.

- `ormbridge.config.json` defines one conversion: `from-efcore`.
- `models/` holds the EF Core model, written by hand: entity classes with data annotations (`Post.cs`, `Category.cs`, ...), a `TimeStamped` base class, the `PostStatus` enum, `PostConfiguration.cs` (an `IEntityTypeConfiguration<Post>` with the relationships, defaults and the join table) and `BlogContext.cs` (the `DbContext`). They describe the same blog schema as [`../schema/schema.prisma`](../schema/schema.prisma). This is one of the examples whose `models/` folder is not generated, so edit these files freely.
- `prisma/schema.prisma` is generated by reading `models/`. It is the same schema as the shared one, apart from the names EF Core implies (for example the columns that have no `[Column]` attribute keep their C# names, `Id` and `Title`).

EF Core claims no file extension (`.cs` is too generic), so the config names `from` explicitly. Nothing is compiled or run: no .NET SDK, NuGet package or database is needed.

Run it (the config file supplies the paths and formats):

```bash
cd examples/efcore
npx ormbridge convert           # regenerate prisma/schema.prisma
npx ormbridge convert --check   # exit code 3 if the generated file is stale
```

Inside this repository, run `npm run build` once and use `node ../../dist/cli.js convert` instead of `npx ormbridge convert`. `npm run examples` regenerates every example and `npm run examples:check` verifies them.

The Prisma file is generated, so edit the models and rerun rather than editing it. See the [Entity Framework Core guide](../../docs/formats/efcore.md) for what is read and what is not.
