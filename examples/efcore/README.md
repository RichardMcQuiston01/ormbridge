# Entity Framework Core example

This folder shows ormbridge converting the shared blog schema to Entity Framework Core 8 models (C#) and back.

- `ormbridge.config.json` defines two conversions: `to-efcore` and `from-efcore`.
- `models/` is generated from `../schema/schema.prisma`: `models/Models/` holds one entity class per model (`Post.cs` with data annotations such as `[Table]`, `[Column]`, `[MaxLength]`, `[Index]` and `[ForeignKey]`) and the `PostStatus` enum with its value converter, and `models/AppDbContext.cs` is the `DbContext` with a `DbSet<T>` per entity and the parts of the mapping that data annotations cannot say (defaults, delete behaviors, the enum conversion) in `OnModelCreating`.
- `prisma/schema.prisma` is generated by reading `models/` back. It is the same schema as the shared one, apart from what EF Core spells differently (for example the join table `blog_post_tags` is an explicit model, the enum members keep the names of the C# enum and the reverse side of `category` is called `postSet`).

EF Core claims no file extension (`.cs` is too generic), so the config names `from` and `to` explicitly. The default `annotations` style puts what annotations can express on the classes; add `"style": "fluent"` to a conversion for plain classes and one `IEntityTypeConfiguration<T>` per entity (`Configurations/PostConfiguration.cs`), and `"namespace": "Shop.Data"` to change the namespace (default `App.Models`).

Run it (the config file supplies the paths and formats):

```bash
cd examples/efcore
npx ormbridge convert           # regenerate models/ and prisma/schema.prisma
npx ormbridge convert --check   # exit code 3 if a generated file is stale
```

Inside this repository, run `npm run build` once and use `node ../../dist/cli.js convert` instead of `npx ormbridge convert`. `npm run examples` regenerates every example and `npm run examples:check` verifies them.

To use the models, copy `models/` into a .NET 8 project that references `Microsoft.EntityFrameworkCore` and a provider (the output is provider neutral, apart from the PostgreSQL column types ormbridge picks by default; pass `--provider sqlite` for SQLite), and give the context a connection:

```csharp
var options = new DbContextOptionsBuilder<AppDbContext>()
    .UseNpgsql("Host=localhost;Database=blog")
    .Options;
using var context = new AppDbContext(options);
context.Database.EnsureCreated();
```

The files are generated, so edit `../schema/schema.prisma` and rerun rather than editing them. See the [Entity Framework Core guide](../../docs/formats/efcore.md) for what is read, written and lost.
