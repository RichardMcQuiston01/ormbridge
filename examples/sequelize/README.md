# Sequelize example

This folder shows ormbridge reading Sequelize 6 models and converting them to a Prisma schema. Sequelize is an input-only format, so there is no `to-sequelize` conversion.

- `ormbridge.config.json` defines one conversion: `from-sequelize`.
- `models/` holds the Sequelize models, written by hand in the layout `sequelize-cli` generates: one `module.exports = (sequelize, DataTypes) => { ... }` file per model, each with `sequelize.define(...)` and an `associate` function, plus the `index.js` loader (it defines no models, so it is ignored). They describe the same blog schema as [`../schema/schema.prisma`](../schema/schema.prisma). This is the one example whose `models/` folder is not generated, so edit these files freely.
- `prisma/schema.prisma` is generated by reading `models/`. It is the same schema as the shared one, apart from the names Sequelize implies (for example `createdAt` and `updatedAt` have no database default, and the post/tag join table is an explicit model).

Sequelize claims no file extension (`.js` and `.ts` are too generic), so the config names `from` explicitly. The foreign key columns that `belongsTo` and `hasMany` add are not written in the models; the reader adds them the way Sequelize does when `associate` runs.

Run it (the config file supplies the paths and formats):

```bash
cd examples/sequelize
npx ormbridge convert           # regenerate prisma/schema.prisma
npx ormbridge convert --check   # exit code 3 if the generated file is stale
```

Inside this repository, run `npm run build` once and use `node ../../dist/cli.js convert` instead of `npx ormbridge convert`. `npm run examples` regenerates every example and `npm run examples:check` verifies them.

The Prisma file is generated, so edit the models and rerun rather than editing it. See the [Sequelize guide](../../docs/formats/sequelize.md) for what is read and what is not.
